Persistent context for anyone (Claude or human) returning to this repo. Skim

## What this is

A single Go binary that runs on a Linux gateway, snoops every DNS reply served
by the local resolver via eBPF, looks each name up in a hot-reloadable suffix
trie of "interesting" domains, and pushes the matching A/AAAA records into
named kernel `ipset`s. Existing `iptables -m set --match-set` rules then
match traffic by domain.

**Out of scope** (do not add without an explicit design change):
- TCP DNS, DoH, DoT.
- Auto-creating ipsets — the upstream rule generator owns lifecycle.
- iptables rule generation.
- Per-rule TTL overrides (use `--ttl-min` / `--ttl-max`).

## Build & development workflow

| Task | Command | Notes |
|---|---|---|
| Regenerate BPF object | `make generate` | Needs `bpftool` + `clang` + libbpf headers |
| Build binary | `make build` | Static, CGO_ENABLED=0; needs generated BPF object |
| Vet | `go vet ./...` | |
| Unit tests | `go test ./...` | No root needed; uses `source/fake` |
| Race tests | `go test ./... -race` | Run before merging anything pipeline-related |
| Integration tests | `make test-integration` | Build tag `integration`; needs root + ipset |
| Format | `gofmt -l .` | Should report nothing |

CI (`.github/workflows/ci.yml`) runs vet + test + build on Ubuntu 22.04 with
the BPF toolchain installed. CI **does not** load the BPF object on a real
kernel — that's the Debian VM smoke test.

### Toolchain prerequisites

- Linux ≥ 5.4 with BTF (`/sys/kernel/btf/vmlinux` must exist)
- `clang` ≥ 10
- `bpftool` (for `vmlinux.h` generation)
- `libbpf-dev`
- Go ≥ 1.24 (bumped by miekg/dns dependency)

WSL2 host caveat: WSL2's bpftool may not parse the WSL2 kernel BTF; you can
hand-write a minimal `internal/bpf/c/headers/vmlinux.h` shim with just the
fields the BPF program touches (CO-RE resolves real offsets at load time).

## Testing strategy

- **Pure-Go packages** (`rules`, `dnsparse`, `dedup`, `pipeline`): full unit
  coverage with no root, no kernel, no real ipset. Pipeline tests use
  `internal/source/fake` to inject canned events and a recording mock for
  the ipset client.
- **`internal/ipset`**: only `ClampTTL` is unit-tested. The netlink path
  needs root + `ipset` binary; gated by build tag `integration` (`make
  test-integration`).
- **`internal/bpf`**: no Go tests. The package compiles only after
  `go generate` produces `bpf_bpfel.{go,o}`. Real verification is the
  Debian VM smoke test in [docs/debian-vm-quickstart.md](docs/debian-vm-quickstart.md).
- **End-to-end**: `dig` against the local resolver, `ipset list` to confirm
  population, optional `iptables -m set` rule to confirm match. See the
  quickstart doc.

## Deploying

Production install + smoke test on a Debian 12 VM is documented step-by-step
in [docs/debian-vm-quickstart.md](docs/debian-vm-quickstart.md). It covers
toolchain, local resolver setup, pre-creating ipsets, systemd install,
verification with `dig` + `ipset list`, atomic-rename reload, optional
iptables integration, metrics inspection, and a troubleshooting table.

The systemd unit at `deploy/dns2ipset.service` grants the three required
caps (`CAP_BPF`, `CAP_PERFMON`, `CAP_NET_ADMIN`) via `AmbientCapabilities=`
rather than running as root.

### Build once, ship as .deb (cross-host)

`make package` produces `dns2ipset_<version>_amd64.deb` from the same
toolchain as `make build`. The .deb is portable across kernels, not just
the build host's kernel:

- **Static binary**: `CGO_ENABLED=0` Go binary — no glibc link, runs on any
  modern Linux of the right arch.
- **BPF object portability via CO-RE**: bpf2go embeds the `.o` into the Go
  binary. Struct field offsets are resolved at *load* time against the
  target kernel's BTF, so a binary built on (e.g.) Ubuntu 22.04 with kernel
  6.5 loads cleanly on Debian 12 with 6.1 or Debian 11 with 5.10. The CO-RE
  field-existence guard on `iov_iter.__iov` ↔ `iov_iter.iov`
  ([internal/bpf/c/dns2ipset.bpf.c](internal/bpf/c/dns2ipset.bpf.c))
  is what makes this work across the 5.x → 6.x rename.
- **Only runtime requirement on the target**: kernel ≥ 5.4 with BTF
  (`/sys/kernel/btf/vmlinux`). The postinst script
  ([packaging/postinst.sh](packaging/postinst.sh)) checks for it and warns
  if missing — install still succeeds, but the daemon won't start.
- **Runtime depends**: `ipset`, `libc6`. Build-time tooling (clang, bpftool,
  libbpf-dev, Go) is **not** a runtime dependency.

Packaging entry points:
- [packaging/nfpm.yaml](packaging/nfpm.yaml) — package metadata, file map.
- [packaging/postinst.sh](packaging/postinst.sh) / [prerm.sh](packaging/prerm.sh) — systemd hooks + BTF check.
- [docs/build-and-package.md](docs/build-and-package.md) — operator-facing
  build-and-install walkthrough.

The original [docs/debian-vm-quickstart.md](docs/debian-vm-quickstart.md)
is now the build-host setup reference; operators of target hosts only
need the build-and-package doc plus the .deb.

## Process notes (how this branch was built)

The initial implementation followed the **superpowers:writing-plans** →
**superpowers:subagent-driven-development** flow: each task was implemented
by a fresh subagent following TDD, reviewed by separate spec-compliance and
code-quality subagents, and committed before moving on — so the commit
history mirrors the task structure 1:1. A holistic final review caught two
correctness bugs (CNAME multi-A drop; pipeline shutdown drain race) that
single-task reviews missed; both were fixed in commit `53b2a57`.

If you're adding a non-trivial feature, prefer writing a plan and running
the subagent flow over hand-coding directly. Architectural invariants live
in [ARCHITECTURE.md](ARCHITECTURE.md) — extend that file when a change
introduces a new design decision worth recording.
